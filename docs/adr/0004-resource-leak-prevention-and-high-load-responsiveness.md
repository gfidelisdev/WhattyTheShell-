# Resource Leak Prevention and High-Load Responsiveness Strategy

We need reliable operation and zero freezing when application load and terminal throughput increase. We identified four root causes: DMA-BUF file descriptor leakage in GdkDmabufTextureBuilder due to missing fd closure upon texture release, main-thread event loop starvation caused by unbuffered non-yielding PTY stream processing, synchronous GPU pipeline blocking via wait_indefinitely() inside WidgetImpl::snapshot, and lingering child processes on closed tabs. We decided to close duplicated file descriptors in the builder release notification callback, introduce a bounded channel (128 chunks) with batched VTE processing up to 64KB and cooperative glib::timeout_future yields under load, replace blocking GPU device polling with non-blocking wgpu::PollType::Poll, and implement WidgetImpl::dispose to clean up inner terminal resources and terminate associated child processes upon tab closure. This ensures stable memory and file descriptor consumption, eliminating hangs under heavy application workloads.
